The design choice

Choose this direction for a deliberate, reassuring first launch. The stable progress rail gives orientation; the permission card separates app preferences from macOS authorization. The tradeoff is a larger three-step setup. Everyday controls remain the existing native controls.

Try it: from this checkout, run sh scripts/run-onboarding-alternative.sh. The separate local bundle uses its own preferences and permission identity. No installation is required.

Evidence: native-view renders, nine onboarding regression tests, and an actual app walkthrough covering saved switches, optional permission, controls, replay, and Quit. Full validation and limitations.

These images render isolated test settings and an empty accessory list. Permission states are fixtures, not a record of permission changes or real notifications. No user telemetry appears in this comparison. This is an alternative concept, not a merged or selected direction.
